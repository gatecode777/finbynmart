## Catalog database (`db/`, built by `npm run catalog:build`)

Source files: `public/sellers.xlsx|csv` (1,200 sellers) and `public/real_clothing_products.xlsx|csv` (21,392 products). Their own Notes sheets state the limits below; none of it is production data.

- **Sellers are fictional.** Emails are `@example.com`, phones are `+91 00000 xxxxx`. Never display them as real contact details. The source `total_products` column (sum 474,936) was dropped because it contradicts the 21,392-row catalog; counts are derived from the `seller_product_counts` view instead.
- **Products are a research dataset.** Names, images, categories and colours come from the Kaggle Fashion Product Images (Myntra) dataset, licensed for learning/research use. Check the license before any commercial use. The names include real brands (Puma, Adidas, …) now attached to fictional sellers — never present that as a real brand/seller relationship.
- **Price and sizes are estimates.** Not in the source dataset; estimated by product type. Stored as `estimated_price_inr` and `product_sizes`. These are retail-style prices — there is no MOQ or wholesale pricing, which a B2B listing will need.
- **Product photos are hotlinked from Myntra.** All 21,392 `source_image_url` values point at Myntra's CDN. The `/products` pages now show them (upgraded to https, loaded directly by the visitor's browser via `unoptimized` next/image — our server neither proxies nor copies them). This is a development/demo setup only: it relies on a third party's server, and the dataset is research-licensed. It also conflicts with the "licensed local images only" rule, so replace with seller-supplied or licensed photos before launch.
- **Assignment is synthetic.** Each product is assigned to exactly one *active* seller by matching its category to the seller's specialization, with 10% going to Multi-category sellers. It is deterministic (fixed seed) but it is not a real seller–product relationship.
- **Source files are web-served.** Anything in `public/` is publicly downloadable, including the research-only dataset. Move `sellers.*` and `real_clothing_products.*` out of `public/` before deploying.
- **How the site reads it.** `src/lib/catalog/data.ts` loads the committed `db/seed/*.csv` into memory (not the `.sqlite` file, so a fresh clone runs with no build step) and `queries.ts` answers every page. It loads only active sellers and never reads seller emails, phones or owner names. On a host that bundles only traced files, `db/seed/` must be included in the deployment. To move to a hosted database, replace `data.ts` and keep `queries.ts`'s signatures.
- **Catalog pages are live.** `/suppliers`, `/suppliers/[slug]`, `/products`, `/products/[slug]` and `/search` read it. Catalog sellers have no verification data so none show as verified, no seller has a genuine logo (a neutral initials placeholder is shown, never an invented mark), and seller profile text is built only from catalog facts (name, city, specialization, product count). The seller hero is the generic apparel category photo, not the seller's premises. Catalog products have no MOQ, rating or reviews, so those are hidden rather than invented; prices are labelled "Est.".
- **Two catalogs coexist.** The earlier hand-built sample profile (Shree Textiles) and sample B2B products (`categoryPages.ts`) still own their slugs; everything else resolves from the catalog. `/category/apparel-fashion` is still the small sample page, not the 21,392-product catalog — the catalog is browsed at `/products`.

## Pages with no real content yet

- **Footer, legal and info pages** (About Us, Blog, Careers, Press, Success Stories, Buyer/Supplier Guide, Safety Tips, FAQs, Help Center, Contact Us, Track Inquiry, Report Abuse, Feedback, Pricing, Supplier Membership, Lead Management, Terms, Privacy, Refund, Cookie, Disclaimer) render an honest "This page isn't published yet" placeholder from `src/app/[page]/page.tsx`, marked noindex. The business must supply the real text — especially legal policies and contact details, which must not be invented.
- **Industry pages** (`/industries/[slug]`) and the four top categories without listings (Home & Lifestyle, Food & Beverages, Agriculture, Chemicals & Dyes) show an empty state, because no supplier data exists for them.
- **Accounts are real but need MongoDB reachable.** Sign In, Create Account (`/sign-up`) and Register as Supplier store users in MongoDB (`users` collection, scrypt-hashed passwords, signed httpOnly session cookie; code in `src/lib/auth`, routes in `src/app/api/auth`). Config is in git-ignored `.env.local` (see `.env.example`). Not yet built: password reset, email verification, rate limiting, route protection, and any supplier dashboard — a supplier account is only a stored registration, it does not create a catalog listing.
- **Top-category tiles link through `/categories/<slug>`**, which redirects to `/category/<slug>` (`packaging-printing` and `machinery-equipment` are aliased to the pages that exist).
- **Site icon** (`src/app/icon.png`, `apple-icon.png`) is generated from the uncropped storefront mark in `public/images/brand/finbyn-mart-logo.png`. It's a PNG; add a `.ico` if you need legacy-browser support.
