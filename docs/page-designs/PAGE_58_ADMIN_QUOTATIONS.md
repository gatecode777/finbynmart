## Permissions
`quotations.read` (new, explicit, default deny) for the page, list and detail, checked on the server. The "View Requirement" link needs the existing `inquiries.read` and the destination enforces it again. No order link: there is no admin order route or order-read capability, so none is offered; an acceptance is never presented as an order, payment or fulfilment. No mutation endpoint exists (POST, PATCH and DELETE on the routes are 405).

## What is a row (inclusion and revisions)
One row = one logical quotation = its CURRENT submitted version (`isCurrent: true`, status not DRAFT). Never rows or counted: a supplier's first draft, a revision draft (`isCurrent: false`, DRAFT), superseded or earlier versions. The `draft` working copy is never projected. The detail shows the current submitted version in full and earlier SUBMITTED versions only as a labelled history table (revision, submitted, status, total, valid until: "(current)" / "(earlier)"); fields of different revisions are never merged. Newest submission first (`sentAt`, never a draft timestamp) with the unique `_id` tie-break; 20 per page (max 50).

## Status and expiry
Status is the existing buyer-facing effective status: persisted status plus `validUntil` at ONE reference time per response (shown on the page). Filters (same conditions as the buyer tabs through the shared `tabFilter`): Active (SENT, valid, more than 7 days left), Expiring soon, Revision requested, Accepted, Rejected, Expired (SENT or REVISION_REQUESTED past `validUntil`), Withdrawn. They partition exactly what the badges show (verified in test 85 over every status and the expiry boundaries). An accepted quotation stays Accepted after its validity date. The buyer-side one-accepted-per-inquiry rule is untouched. Reading never writes, and never touches a timestamp.

## Money
Amounts are shown from the version's own stored fields through the existing `totals` / `breakdownRows` helpers, plus the stored commercial snapshot (total and tax rule), never from today's catalogue, tax configuration or supplier profile. Currency and unit stay with each amount; currencies are never combined and nothing is labelled revenue. If the snapshot total differs from the total calculated from the stored fields, or the amounts cannot be calculated, or there is no snapshot, or the requirement record is missing, a neutral "Data notes" box says so and nothing is rewritten. The snapshot's raw inputs are excluded from the query.

## Detail content
Reference and revision; submitted time; status and valid until; source (Direct inquiry / General requirement from the inquiry's `sourceType`); supplier name with a relation label (General Requirement: "Responding supplier"; direct and same as the selected supplier: "Selected supplier"; direct but another company: "Matched supplier"); requirement reference; buyer requested vs supplier offered product and quantity; unit price; price breakdown; commercial terms (missing = "Not provided"); the recorded buyer decision as type and date only (no buyer reason, no revision-request message); revisions. Never present: buyer contact or personal detail, private messages, internal notes, attachments, draft data, credentials.

## API
`GET /api/admin/quotations?q=&status=&page=&limit=`: `q` must be a reference (letters, digits, hyphens, up to 40; anything else is a 422), unknown status/page/limit is a 422; the search is an anchored escaped upper-case prefix on the quotation or requirement reference. `GET /api/admin/quotations/[reference]`: unknown, malformed and draft-only references give the same 404. Both: rate limit 240 per 10 min, `private, no-store`, `{ ok, message, fields }`. Indexes added (lazily, by the service): `admin_quotations_newest (isCurrent, sentAt, _id)` and `admin_quotations_by_requirement (inquiryReference, sentAt)`; the reference prefix uses the existing `quotation_version` index. One list query (skip/limit, projection) plus one count; the detail is two reads (history and requirement) in parallel.

## UI
Search and Status apply together on Search; Reset restores defaults; only reference text, status and page are in the URL; stale responses are ignored; a failed request shows the message with Retry and keeps filters and rows (never an empty list); empty states "No submitted quotations yet." and "No quotations match these filters."; a table with a caption on desktop and cards on mobile; a read-only drawer (native dialog) with loading, error, 404 ("not found, or it has not been submitted"), 403 (no Retry) and missing-related-record states; status is a text label as well as a colour; the note states that amounts keep their own currency and that the page is read-only. The design board's sample references, suppliers, amounts and arithmetic are not used.

## Gaps and decisions
No admin order view exists, so a quotation's related order cannot be shown or linked; if one is built later it needs its own capability. The detail is the current version only (an earlier version is summarised, not opened in full). Supplier-name search and filters were not added (no supported identifier with an authorization rule). The quotation attachment and PDF features remain BLOCKED in the existing system and are not shown.
